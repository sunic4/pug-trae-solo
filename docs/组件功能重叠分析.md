# Canvas Compose 组件功能重叠分析

## 1. 概述

本文档分析了 Canvas Compose 组件库中存在的功能重叠问题，并提供了相应的优化建议。

## 2. 功能重叠分析

### 2.1 Box vs Padding

**Box 组件**
- 支持 padding 属性
- 功能完整的容器组件

**Padding 组件**
- 专门用于添加内边距
- 支持细粒度 padding 控制（paddingLeft, paddingRight, paddingTop, paddingBottom）

**重叠问题**
- Box 组件已经支持基础 padding 功能
- Padding 组件提供了更细粒度的 padding 控制

**建议**
- 方案 1：保留 Box，移除 Padding 组件
- 方案 2：增强 Box 组件，增加细粒度 padding 属性，移除 Padding 组件
- 方案 3：保留两者，将 Padding 作为 Box 的辅助组件

### 2.2 Column + Row vs Container

**Column 和 Row 组件**
- 专门的行列布局组件
- 简单易用

**Container 组件**
- 支持 direction 属性，同时实现行列布局
- 支持对齐（align）和间距（justify）配置
- 功能更强大

**重叠问题**
- Column 和 Row 功能可以完全被 Container 替代
- 多个组件做相似的事情，增加了学习和使用成本

**建议**
- 方案 1：保留 Container，移除 Column 和 Row
- 方案 2：保留 Column 和 Row 作为 Container 的简化版本
- 方案 3：统一使用 Container 组件，提供更全面的布局功能

### 2.3 List vs Column/Row/Container

**List 组件**
- 专门的列表组件
- 支持垂直和水平方向
- 有 key 概念，便于更新

**Column/Row/Container 组件**
- 也可以实现列表功能

**重叠问题**
- List 组件的功能可以通过其他布局组件实现
- 但是 List 组件有特定的语义（列表）

**建议**
- 方案 1：保留 List 作为语义化组件
- 方案 2：移除 List，使用 Container 实现列表

### 2.4 Spacer 组件

**功能**
- 简单的占位组件，用于创建空间
- 独特功能，无明显重复

**建议**
- 保留 Spacer 组件

## 3. 推荐架构

### 3.1 核心布局组件

**Container**
- 作为通用布局组件
- 支持 direction, align, justify 等属性
- 替代 Column 和 Row

**Box**
- 作为基础样式容器
- 支持背景色、边框、圆角等
- 增强 padding 属性支持（细粒度控制）

**Stack**
- 作为堆叠布局组件
- 保留现有功能

### 3.2 特殊用途组件

**List**
- 保留作为语义化列表组件
- 提供列表特有的功能

**Spacer**
- 保留作为占位组件

### 3.3 移除的组件

- Padding：功能合并到 Box
- Column：功能合并到 Container
- Row：功能合并到 Container

## 4. 迁移指南

### 4.1 Column/Row 迁移到 Container

```typescript
// 之前
ColumnComponent({
  padding: 10,
  spacing: 10,
  children: [...]
})

// 之后
ContainerComponent({
  direction: 'column',
  padding: 10,
  spacing: 10,
  children: [...]
})
```

### 4.2 Padding 迁移到 Box

```typescript
// 之前
PaddingComponent({
  padding: 10,
  child: [...]
})

// 之后
BoxComponent({
  padding: 10,
  children: [...]
})
```

## 5. 总结

通过梳理组件功能，我们发现了一些可以优化的地方，包括：
1. 合并相似的布局组件
2. 增强核心组件功能
3. 减少组件数量，降低学习成本
4. 保持语义化组件（List, Spacer）
